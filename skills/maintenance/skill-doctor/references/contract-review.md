# 必要约定检查

检查指令是否充分说明完成任务所需的内容。只检查实际适用的方面，不要求统一章节布局；AGENTS.md 同样按其职责判断。

| 检查方面 | 写作与检查关注点 |
| --- | --- |
| 适用范围 | Skill 的用途、触发和排除条件是否明确；AGENTS.md 中规则适用的项目、目录和情形是否明确。 |
| 执行流程 | 动作、顺序、分支、循环、回退和停止条件是否保留必要依赖。 |
| 工具使用要求 | 工具名称、必需参数、前置条件、预期结果和错误处理是否足以支撑有效操作。 |
| 规则及适用条件 | 明确在什么条件下必须、禁止或优先做什么；避免将局部要求扩大到无关情形。 |
| 输出要求 | 输出类型、字段、顺序、校验和完成条件是否满足真实交付要求。 |
| 示例与说明 | 是否需要示例、模板或理由帮助理解；其中是否包含正文未表达的必要要求。它们不能替代实际运行的验证结果。 |

合并前比较规则的含义、适用范围和条件，而不只比较措辞。集中说明重复规则时，不扩大其适用范围，例外紧邻对应规则；复用流程时，保留开始条件、结束条件和步骤依赖。抽取重复内容应减少表达负担，或解决已证实的维护不一致、适用边界不清等问题；收益不足以抵消新增说明和引用负担时，保留原写法。按需加载与消除重复分别判断，移入参考文件本身不代表已经精简。

删除示例前，将它独有的必要条件或字段明确写入对应约定，再判断示例是否仍有解释价值。例如，正文只要求“报告任务状态”，而模板还要求失败时给出原因；删掉模板时应保留失败分支的原因要求，不能只留下状态字段。

维护时优先修改已有规则：重复提醒无需追加，新的条件或例外归入相关规则，真正新增的要求才新增内容。改变或删除要求应有任务或既有约定作为依据；忠实保留旧文并不能证明旧要求仍然合理。
