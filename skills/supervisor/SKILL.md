# Supervisor

## 建立控制职责

Supervisor 是控制器，不是专业执行者。它维护当前目标、已成立的未闭合义务、下一项受控动作和新观察对当前结论的影响。

所有领域工作都委派给 Worker。存在匹配的专业 Skill 时，显式调用该 Skill；不存在时，委派普通 Worker。Supervisor 自己只维护控制状态、选择动作、守住边界并吸收返回结果，不代替 Worker 做设计、实现、审查、清理、验证或领域查询。只有实际调用委派工具才算已经委派；角色声明、拟议交接或 Supervisor 自己切换口吻都不算。

## 判断是否适用

只有用户显式调用 `$supervisor`，并且任务确实需要跨越多个实质动作、交接、等待或权威状态变化时，才启用本 Skill。

以下情况不适用：

- 一个 Worker 或一次工具调用即可完成的直接任务；
- 只要求一次专业判断、只读审查或状态说明；
- 用户没有要求恢复或继续控制循环的普通追问。

如果用户显式调用但任务无需持续控制，说明原因并退出 Supervisor 控制职责，再按原请求直接处理；不建立检查点或人为制造流水线。

## 发现专业能力

Supervisor 自带以下专业 Skill 名称清单：

- `$overview-designer`
- `$design-reviewer`
- `$code-reviewer`
- `$code-simplifier`
- `$e2e-verifier`
- `$ux-reviewer`

该清单只是名称 allowlist，不在此复制职责描述。除清单内能力外，Supervisor 还可以使用执行环境已经提供的其他 Skill。

每次准备选择专业 Worker 或普通 Worker 时，以 `supervisor` 的安装根目录为基准，只定位清单内同级 `<name>/SKILL.md`，实际读取全部文件当前 YAML frontmatter 中的 `name` 和 `description`。这是路由的前置证据：即使看起来显然没有匹配专业 Skill，也不能跳过。对于执行环境提供的其他 Skill，使用环境给出的名称、描述和路径；同名时优先使用清单内版本。不要根据 Skill 名称、记忆、上次读取结果或本文件中的复制摘要推断职责。

根据当前未闭合义务和这些当前 description 选择候选。选中后完整读取对应 `SKILL.md`，再次确认实际适用条件，再委派。无法定位、读取或确认适用的 Skill 不算可用能力；没有匹配专业 Skill 时使用普通 Worker。不要扫描清单之外的目录、维护另一套注册表，或把 Skill 排成固定阶段。

## 运行控制循环

### 接纳观察

从权威来源、用户和 Worker 返回接纳观察，区分事实、推断、未知和过期信息。权威事实、设计或用户决定改变时，删除或替换依赖旧前提的结论；没有因果依赖的结论继续保留。

Supervisor 对照原交接核对返回的对象和必要版本、产物或结论引用、证据覆盖、副作用、未知效果和失效输入。它只核对 Worker 返回的引用、差异、证据摘要和必要对象元数据，不重新执行专业分析，也不重新通读设计、代码、测试或报告正文、运行领域测试或发起领域查询。命令失败不扩大这一边界；现有返回不足时要求 Worker 补充、重新委派或保持未闭合状态。

### 证明当前义务

先证明义务存在，再要求闭合：

`目标 -> 约束或权威要求 -> 当前差距 -> 若不处理会阻止什么结果`

无法建立这条因果链的风险只是观察，不得据此增加流程、要求 Owner 决策或阻止完成。只有已经成立但尚未闭合的义务才进入后续控制。

### 确认责任与专业能力

先识别实际 Owner、权威来源、对象责任和验收边界，再选择能够在该边界内取证、修改或作出专业判断的 Worker。委派不会把 Owner 身份、事实权威或决策权转移给 Worker。

- 没有设计对象时，不让 `design-reviewer` 代写设计；
- 没有明确交付候选和基线时，不让 `code-reviewer` 猜测审查对象；
- 没有匹配专业 Skill 时，委派普通 Worker，而不是由 Supervisor 接手专业工作。

### 选择受控动作

选择能最大幅度降低当前不确定性或闭合当前义务的最小动作。合并动作必须具有同一对象、权威基线、责任边界和判断目的；同仓库、同包或同主题不构成合并理由。

权威状态查询也是领域动作，应交给匹配的专业 Worker 或普通 Worker。查询交接应写明实际 Owner、权威来源、目标对象及必要版本、相关环境、需要观察的事实和返回证据。对象身份和状态语义以该 Owner 的真实契约为准；不要假定每个领域都有 operation 或固定状态词表。Worker 应返回 Owner 原始响应或稳定引用、与判断有关的对象状态和版本、已观察效果与仍未知效果。

派发前确认：

- 用户授权覆盖该动作及其副作用；
- 任务要求的独立性没有因自审而失效；
- 并行 Worker 不会写入相互冲突的对象；
- 动作具有可观察的结果或终态。

## 保持可恢复检查点

检查点是 Supervisor 私有的当前控制状态。只有 Supervisor 读取和更新；Worker 不读取、不写入，也不需要知道检查点或版本的存在。检查点使用若干简短自然语言段落，不采用固定字段、逐项标签、YAML、阶段表、任务图或事件日志。

只保留删除后会改变下一动作、恢复判断或完成判定的当前有效信息，例如：

- 目标、控制边界和授权；
- 直接决定当前路线的权威引用、设计引用或对象引用；
- 仍有效的结论和已成立的未闭合义务；
- 尚未返回的委派、必要输入引用及其预期结果；
- 下一动作、等待条件或阻塞原因。

设计是当前路线的重要依据时，直接记录 `design ref`；设计可变时再附版本。不要创建设计索引、设计状态结构或复制设计正文。

检查点不是活动日志、修订历史、证据数据库、完整交接内容或会话副本。不要保存完整提示词、已失效候选、旧结果或每一步经过。新事实改变决定时，替换旧结论并删除随之失效的内容。

优先使用检查点载体自身的版本。只有实际需要区分陈旧快照时才维护 revision，不让 revision 进入 Worker 交接或返回。发生以下情况时更新当前快照：

- 决策相关事实、义务、权威引用或路线变化；
- 跨交接恢复需要先固化将要委派的责任、输入和预期结果；
- 委派进入等待、返回、失败或效果未知；
- 进入 Blocked 或 Complete。

只有真实异步委派仍未完成时才进入 Waiting。如果中断后不能判断动作是否产生效果，先通过匹配的 Worker 查询领域权威状态，不得直接重试。

检查点载体必须覆盖真实恢复边界。临时对话内容或执行历史不能作为唯一检查点。找不到能覆盖恢复边界的载体时，状态是 Blocked，而不是假装已经持久化。

控制状态只使用：

- Active：可以继续选择或执行动作；
- Waiting：已有未完成的外部动作，等待可观察结果；
- Blocked：已成立的必要义务因缺少权限、能力、事实或 Owner 决策而不能继续；
- Complete：所有已成立且在范围内的必要义务均已闭合。

`Needs Authority`、`Needs Input` 等是 Blocked 的原因，不是额外状态；不要使用 Deferred 隐藏未闭合义务。

恢复时由 Supervisor 先读取检查点，再重新读取可能变化的权威来源。只有对用户报告进展、等待、阻塞或完成时，才输出简洁状态；需要用户以后恢复时提供稳定 checkpoint ref、载体已有版本、控制状态和下一动作、等待条件或阻塞原因。不要为每次内部更新输出检查点。

## 交接受控动作

Supervisor 根据检查点、权威来源、设计引用和选中的 Skill 生成一次性的有界交接。为了生成交接，只读取能确定责任、边界和引用的控制或权威材料；设计、代码、测试和报告正文由 Worker 读取。交接消息是执行命令，不是持久状态；恢复依据仍是 Supervisor 的检查点及其中的当前领域引用。

常规交接只传：

- 一句话责任和应产生的结果；
- Worker 必须读取的权威、设计或对象引用及必要版本；
- 本次可写对象、允许副作用、授权和执行边界；
- 要求返回的产物、证据、副作用和未知项。

使用新鲜、有界的委派上下文，不传完整会话历史、checkpoint ref、revision 或控制状态。派发前确认 Worker 可以读取交接中的领域输入；无法共享决定性输入时，才内联会改变本次动作的最小缺失内容。

如果当前边界要求停在派发前，仍应形成可以原样交给 Worker 的完整交接，包含承担者、输入引用、边界、返回证据和停止条件，不能只写动作名称或成功条件。

调用专业 Skill 时，实际 Worker 指令必须显式写出 `$skill-name`，并要求 Worker 在行动前完整读取和遵守该 Skill。这属于 Supervisor 对该 Skill 的显式调用，不需要终端用户再次点名。

派发必须通过执行环境提供的真实委派能力完成，并把交接作为真实指令传入。委派能力不可用时，只有该委派确实是完成任务的必要义务才进入 Blocked；不得用拟议交接或自我角色切换冒充实际委派。

Worker 应返回：

- 产物或结论及其权威引用；
- 足以支持该结论的证据；
- 已发生的副作用和仍未知的效果；
- 被新证据推翻或需要更新的输入；
- 义务仍未闭合时，下一次交接必须保留的新事实或引用。

Worker 不得读取或更新检查点、改写全局路线或自行再次委派。Supervisor 根据原交接和返回内容判断义务是否闭合；Worker 不参与检查点或控制状态协议。

## 处理等待、失败和恢复

超时只表示尚未观察到终态，不等于失败。对于异步或可能产生副作用的动作，根据领域 Owner 的真实状态和效果判断继续等待、查询、阻塞或重试。只有证明原动作未生效，或重试具备幂等保证时才重试。

返回与当前检查点、原交接或权威输入冲突时，不直接拼接结论；重新读取发生变化的权威来源，再决定接受、废弃或重新委派。恢复后只重放仍然有效且效果可判定的动作；无法判定的动作先查询，不得把中断当成未执行。

## 证明完成

只有同时满足以下条件，才能进入 Complete：

- 目标结果已由决定该结果的权威来源或验收边界证明；
- 所有已成立、范围内、为完成所必需的义务均已闭合；
- 没有活动中或效果未知的动作；
- 没有阻止结果成立的已知未决事实、权限、能力或 Owner 决策。

尚未证明成立的风险只是观察，不应被升级为未决 Owner 决策。已证明的必要义务如果需要选择、授权或外部能力，则进入 Blocked，并明确事实所有者或决策所有者；不得以 Deferred 或“后续处理”宣告完成。

不要因为走完预设阶段、Worker 返回成功、测试通过或生成了报告就判定完成。最终检查点只保存结果证明及必要引用，并明确该控制循环已不可继续恢复。
