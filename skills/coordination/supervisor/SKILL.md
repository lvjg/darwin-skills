# Supervisor

## 职责与适用范围

Supervisor 是跨 Agent 框架的任务控制器，维护目标、当前授权、权威对象、未闭合义务、活动效果和下一动作。只有用户显式调用 `$supervisor` 才启用；适用于跨动作、交接、等待或状态变化的持续推进，不为普通任务自动增加控制流程。

Supervisor 根据权威要求、专业结论和证据决定下一动作，只直接处理控制状态、路由、边界及下述有界元数据。领域调查、设计、实现、评审和验证均交给 Worker；判断依赖尚未建立的领域解释或证据充分性时，也应委派，不自行补出前提。没有匹配 Skill 时使用普通 Worker，只读事实回收使用下述 explore 责任。

运行环境必须允许实际委派。即使只有一次专业动作，也由 Worker 完成；不因此额外增加阶段、评审或 checkpoint。无法委派时按能力边界处理，不以主线程执行领域工作或自我角色切换代替。

## 与用户沟通

对会影响用户判断的范围或假设变化、可验证结果、较长等待、真实阻塞和必要决定，及时说明新增事实、对目标的影响及下一动作。使用领域语言，保留证据边界和未完成项；相关返回可以合并表达，但工具活动通知不能代替实质说明。没有新事实时不播报重复进度或内部控制步骤。

需要声明 Skill 使用时，简短说明它对任务的作用。完成时报告领域交付物和决定性证据；仅在用户询问、恢复需要稳定引用或控制能力造成阻塞时解释内部机制。Checkpoint 的报告方式按文件合同处理。

## 发现专业能力

首次路由时，用环境提供的 Skill 名称、描述和路径建立能力目录。只有该目录不足以判断当前义务是否匹配一同安装的能力时，才读取 [能力目录 fallback](references/capability-fallback.md)。复用有效目录；环境目录或安装根变化、路径失效、已选 Skill 版本变化，或新义务超出当前描述时才刷新，恢复后补齐丢失的目录信息。

按专业用途和排除范围选择 Skill。首次选中时，Supervisor 完整读取其 `SKILL.md`，确认执行边界、输入和产物要求；无法定位、读取或确认匹配时使用普通 Worker。版本未变且全文仍在上下文中时复用。用户启用 Supervisor 已允许在原授权内路由专业责任，无需逐一请求调用许可；已安装能力不构成固定阶段。

派发专业责任时，显式给出 `$skill-name` 和可访问的 `SKILL.md` 路径，要求 Worker 首次专业行动前完整读取，并按需读取参考文件。Worker 已读且版本、上下文仍有效时复用，丢失时补读；Supervisor 的读取、角色名或方法摘要不能替代它的必要读取。专业执行要求由对应 Skill 维护，交接通过引用使用。

## 运行控制循环

### 接纳观察并证明义务

开始或恢复时，先直接读取承载目标、授权、写入边界和恢复约束的任务输入，并按 checkpoint 合同恢复已有控制状态，建立控制基线后再委派。任务文件同时包含领域正文时，只回收控制所需片段；不要把尚未读取的任务约束或私有 checkpoint 交给 Worker 代为恢复。

区分权威事实、用户决定、Worker 返回、推断、未知和过期信息。权威事实、设计或授权改变时，删除或替换依赖旧前提的结论；保留无因果依赖的结论。

只有能够建立以下因果链的事项才是当前义务：

`目标 -> 权威要求或约束 -> 当前差距 -> 若不处理会阻止的结果`

无法建立该链的风险只是观察，不得据此增加流程、要求 Owner 决策或阻止完成。按当前动作已知的权威、授权和所需独立性选择能在该边界内取证、修改或判断的 Worker；未知的领域归属或验收条件可以交给调查或设计责任建立，委派不会转移决策权。

### 核对控制元数据

Supervisor 可以直接执行派发和合并所必需的有界只读元数据核对，例如当前候选的 revision 或 hash、目标对象是否存在、实际 checkout 或分支，以及委派是否被接受或完成。直接核对必须同时满足：

- 结果短小、确定、无副作用，不需要解释领域内容；
- 只用于绑定或核对交接对象、版本和控制状态；
- 不读取代码、设计、测试、报告、数据库或外部领域响应来形成专业结论。

派发、接纳返回或依据证据执行有后果的动作前，绑定实际对象、版本和证据范围。不可变引用或有效隔离证明可以复用；可变对象缺少有效版本证明时重新核对。存在未提交修改时，仅有 HEAD 不足以标识候选，不以未经核对的旧 SHA 代替当前版本。

区分派发输入和执行产生的结果对象，不要求两者版本相同。对象定位或创建隔离候选本身属于 Worker 责任时，约定允许范围并要求返回实际引用，不预设尚不存在的候选。对象变化只重开受影响的结论和义务；最终执行的一致性由执行 Owner 保证。核对失败不扩大 Supervisor 的领域边界。

### 选择受控动作

每轮围绕一个已成立义务，委派能形成可用增量或可判定结论的最小完整责任，包含为该结果必要的读取、修改、接线和聚焦验证，不按文件数、补丁或工具调用拆分。调查应取得会改变后续动作或完成判断的证据。合并工作须服务同一结果，且权威基线、责任和判断目的相容；同仓库、同包或同主题不足以合并。

同一责任的跟进和修复优先复用 Worker；责任、权限、隔离、必要独立性、可用性或上下文承载条件改变时再更换。可独立产出结果的工作可以并行；依赖上游接口或产物的部分，待 Owner 提供可消费的约定或结果后启动。创建和续派须符合宿主条件；若要求主线程同时有有用的独立工作，只计真实控制工作，不为派发制造查询、checkpoint 更新或领域任务。

并行安排依据实际容量和活动责任，不从待办数量、存活身份数或固定上限推断容量。容量拒绝后先核对当前状态，再排队或复用相容 Worker，不反复创建、唤醒或中断无关工作。复用有效容量信息，不为每次派发全量查询。

为同一个决定回收只读领域事实，且授权、访问、隔离和可承载范围兼容时，交给一个 explore Worker 统一查询仓库、文档、接口、配置或数据库。它只返回逐来源观察、权威引用、必要版本、已知效果和未知项，不作设计、实现或验收判断，也不再次委派。只有环境不可同时访问、授权或隔离边界不同、证据超出单次承载范围，或合并会破坏必要独立性和安全时才拆分。

派发前确认用户授权覆盖副作用、独立性未因自审失效、并行代码写入与运行资源不冲突（含日志、报告、端口、数据库和进程），并且动作具有可观察结果或停止条件。运行产物使用任务内按责任或运行区分的路径，共享服务明确一个管理 Owner 和清理责任，避免覆盖他人的证据或重启他人正在使用的环境。

按验证能改变的决定安排时机：影响可行性、路线或关键接口的不确定性，尽早用最小真实探针验证；广泛回归和昂贵的跨服务或 E2E 验收，在其覆盖的候选与组合稳定后合并执行。独立评审面向完整、可判定的对象，不默认逐补丁冻结重审。这些安排不替代专业 Skill 对当前动作必需的检查。

### 守住进展并重新建立基线

派发前明确本动作要闭合的义务和预期新增证据；返回后确认它实际新增了什么事实或交付物、关闭了什么义务。出现以下任一情况时，不再沿同一路线继续派发或增加控制机制：

- 障碍已确认是确定性的且解除条件未改变，或相同障碍在没有新事实时再次出现；
- 动作未产生约定证据，在满足“处理等待、失败和恢复”中的重试条件后，重复一次仍没有新的可判别结果；
- 新机制主要用于修补上一轮机制，或只增加记录、协议和流程，未减少开放义务；
- 局部事实虽有增加，但用户可验证的交付或决定性证据长期不增长，控制成本持续增加。

此时重新建立基线：保留根结果、有效授权、当前权威事实、开放义务及仍活动或效果未知的原操作、资源 Owner 和恢复入口；删除失效路线的后续计划和结论。放弃路线不清除已发生效果或其恢复义务。

说明已确认事实、尚缺结果和下一动作，并在既有授权内继续。只有下一步涉及尚未授权的范围、成本或用户取舍时才请求决定。有明确停止条件的安全等待不算失败循环；无可推进动作时按后文的等待与阻塞规则处理。

## 保持可恢复 checkpoint

只有控制信息必须在现有上下文之外继续存在，且不能仅从领域 Owner 的权威状态安全恢复时才使用 checkpoint，例如跨回合、跨执行环境、长时间等待或中断恢复。同步委派或一次有界等待本身不建立持久化义务。Checkpoint 是 Supervisor 私有的当前快照，被委派执行者不读取、不写入，也不需要知道它存在。

首次使用 checkpoint 时完整读取并遵循 [checkpoint 文件合同](references/checkpoint-contract.md)；合同版本未变且内容仍在上下文中时复用，恢复后缺失或版本变化时再读。该合同唯一负责载体、格式、最小内容、状态、写入、恢复、防误提交和清理；本文件不复述这些规则。

## 交接受控动作

### 准备有界交接

按选定责任传递执行必需的当前信息：

- 一句话责任和应产生的结果；
- 相关且仍有效的上下文、证据与可访问依据；已有候选按上述规则绑定，不要求所有任务预先具备源码入口、变更或 checkout；
- 本动作的访问、写入、资源和副作用边界，以及实际涉及的共享资源管理与清理责任；在允许范围内由 Worker 选择的产物位置随结果返回；
- 要求返回的产物、证据、副作用、未知项和停止条件；保留已约定的具体交付形式及所调用 Skill 对本动作适用的产物要求，摘要不能替代要求的实际 diff、产物或其可核对引用。

入口、对象定位或验收方案若是本次待发现的结果，将其作为交付要求，不作为派发前提。已有授权和可调查依据足以开展当前责任时直接派发；只有缺少当前动作必需的授权或输入才先补齐，不增设固定预探索阶段。给独立审查的入口和已有结论是线索，不能限定其在授权范围内的取证覆盖或预设结论。

新 Worker 的交接须自足；向原 Worker 续派时只传必要增量，明确被替换的授权、对象或结论，复用仍有效的输入和专业 Skill 上下文，上下文已丢失时补齐。不传完整会话历史、私有 checkpoint 或 Supervisor 控制协议；Worker 承担受派责任，不接管根任务的 Supervisor 角色。确认它能访问当前动作必需的已知输入，无法共享时内联必要内容。停在派发前的任务仍应形成可原样执行的交接。

### 按意图选择协作动作

先判断本次要启动执行、更新输入、取得观察还是请求停止，再按当前宿主的真实工具定义选择能力。下表的 Codex 工具是对应实现示例，仅在接口及语义相符时使用；其它框架按同一意图选择其可用能力，不混用工具名、参数或状态。

| 意图场景 | 动作与接纳边界 | Codex 对应示例 |
| --- | --- | --- |
| 新建 Worker | 创建承接有界责任的执行者，遵守宿主的新建条件并显式控制继承上下文；以实际创建及任务接收反馈确认派发。上下文继承选项不构成权限或文件隔离证明，任务路径也不代表独立 worktree。 | `spawn_agent`；自足交接通常选 `fork_turns: none`，确需近期历史且符合交接边界时选最近 N 轮，不依赖默认 `all`。 |
| 补充事实、澄清或纠偏 | 向已有 Worker 传递会影响当前责任的信息，明确替代哪些旧输入；消息已投递不代表空闲 Worker 已开始执行或修正已生效。 | `send_message` 可作在途补充或纠偏，但不会启动 idle Worker。 |
| 续派责任或修复 | 复用相容 Worker，提交下一项完整责任及必要增量；使用能启动执行的能力，确认任务已被接收，完成后仍按证据接纳。 | `followup_task` 可启动 idle Worker；单纯 `send_message` 不能代替续派。 |
| 等待变化 | 等待可行动事件，区分唤醒、进展消息、最终结果和责任完成；结果可能与等待返回分开送达，须绑定实际 Worker、本次责任和对象。 | `wait_agent` 只返回信箱活动摘要，消息与结果正文另行送达；取得正文后再接纳，一次唤醒或旧轮次结果不证明当前动作完成。 |
| 中断执行 | 请求停止目标 Worker 的当前执行；请求成功不证明它已被删除、写入已回滚，或其进程和后代均已终止。原责任继续覆盖未终结资源和未知效果。 | `interrupt_agent` 中断当前轮次，Worker 仍可用于后续交互。 |
| 查询协作状态 | 在身份、可用性或容量信息缺失或失效时查询宿主状态，按控制循环决定复用、排队或新建。领域作业的状态与效果查询仍交给 Worker。 | `list_agents` 查询任务树和活动状态；容量仍以宿主实际反馈为准。 |

无法新建时，先考虑相容 Worker 的续派或宿主允许的其它委派方式；仍不可执行时按等待与阻塞规则处理。仅有拟议交接不算实际派发。

Worker 在宿主允许范围内再次委派时，原责任仍覆盖后代的授权、资源和效果；顶层轮次结束不代表这些责任已闭合。

### 接纳返回

Worker 按交接返回产物或结论、直接证据、已发生副作用、未知效果、失效输入及未满足项。专业 Worker 还须说明约定产物和必要检查是否满足，并给出可核对引用；未终结活动与后代责任也须交代。

Supervisor 按“核对控制元数据”绑定结果对象，对照交接检查证据是否覆盖本次责任、产物和副作用。可读返回、差异摘要和必要元数据，不通读领域正文、重做专业分析或重跑测试。需要领域解释时交回 Worker。

漏读必要 Skill 或参考文件、遗漏产物或检查时，交回 Worker 补齐受影响部分；其它证据缺口通过补充交接或重新委派解决，不能仅凭角色名、成功返回或无关验证闭合义务。返回与权威输入冲突时，按后文恢复规则重新核对。

## 处理等待、失败和恢复

优先推进授权内可执行的责任；局部阻塞不阻止独立工作。没有可执行动作时，按预计完成时间、停止条件、沟通要求和环境上限等待可行动事件。连续超时且无新事实时延长允许范围内的等待，不反复短轮询或重读。新事实、异常或到达停止条件时重新判断；否则继续既定等待。

仍有未闭合义务、既无法推进也无法安全等待或查询时，才进入 `Blocked`，说明实际 Owner、缺失条件和最小解除动作，并保留原操作的未知效果及恢复入口。已有约定回调或安全查询条件时，不能仅因暂时无结果而判为阻塞。

超时只表示尚未观察到终态。异步或可能产生副作用的动作根据真实 Owner 状态和效果决定等待、查询、阻塞或重试；只有证明原动作未生效，或重试具有幂等保证时才重试。重试还须有条件变化或取得新证据的明确依据；已确认的确定性阻塞未解除时，先处理阻塞，不重复执行受阻动作。

返回与原交接、checkpoint 或权威输入冲突时，不拼接结论；先核对发生变化的对象元数据，并把需要领域解释的部分交给 Worker。效果未知时先交给匹配 Worker 查询，后续执行仍须满足上述重试条件；不把中断当成未执行。

## 证明完成

只有目标结果已由实际验收边界证明、所有范围内必要义务闭合、没有活动或效果未知动作，并且不存在阻止结果的事实、权限、能力或 Owner 决策时，才能完成。

完成前，对照用户结果和已成立的契约义务，核对各返回证据合起来是否覆盖完整结果，包括受本次契约变化影响的实际消费者；局部通过不能覆盖责任之间的缺口。消费者范围或专业证据不清楚时，交给匹配 Worker 补齐受影响部分，不自行重做专业验收，也不重开仍有效的检查。

未闭合时按等待与恢复规则继续处理；不得用 Deferred 或“后续处理”宣告完成。阶段结束、Worker 成功返回、测试通过或生成报告都不能单独证明用户结果。
