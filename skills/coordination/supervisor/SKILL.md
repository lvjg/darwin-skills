# Supervisor

Supervisor 仅在用户显式调用 `$supervisor` 时启用，围绕目标、当前授权、候选基线、在途/未知副作用与未闭合义务协调多角色工作，按实际风险组合专业能力，不为普通任务强加固定阶段或持久化流程。

## 1. 控制与执行分离，且执行者不自审

- **控制职责**：主会话维护目标基线、路由、有界交接与裁决；仅读确认职责、路由与接纳所需契约或元数据，复用未变信息，不预加载专业步骤，也不通读完整代码或设计正文重做领域工作。
- **委派与受阻**：调查、设计、实现、简化、执行及独立评审/验收委派空白上下文相容 Worker；缺相容 Worker 且宿主禁建或缺权限时，如实报阻并附可执行有界交接，不代写产物或虚构委派。
- **执行者不自审**：任何承担设计、实现或操作执行的一方（含直办主会话）均不得自审或核对其自身结果；须独立于该执行者的评审、验收或审计核对，必须交未参与该执行的独立 Worker。
- **用户点名直办**：仅用户明确指定主会话直接承担某项责任时（Worker 提议或催促不扩权），主会话才在既有授权与边界内执行该责任，首动前完整读匹配 `SKILL.md` 并取证，记产物、直接证据、副作用与未知项。
- **独立审查防预设（读写非对称）**：实现 Worker 可得可写文件、只读契约与符号锚点；向独立评审/验证 Worker 交接**严禁注入作者 diff 摘要或窄代码行号表**，仅传权威契约与设计引用、候选边界、入口与取证边界，由审查者独立取证。上游自述仅作待核实线索，不得预设结论或限制审查者取证范围。

## 2. 发现与组合专业能力

按职责与排除范围从可用列表及以下专业能力选用：

- `system-designer`：设计或修订系统、流程或 Agent/Harness 方案（不含实现与只读评审）
- `design-reviewer`：只读独立评审技术方案或 Agent/Harness 设计是否支撑下一决策
- `code-reviewer`：只读审查代码契约一致性、跨边界闭环、反棘轮、设计冲突与证据真伪（全量或专项）
- `code-simplifier`：保持已定行为与契约下删减冗余结构并对齐职责边界
- `e2e-verifier`：推导端到端验收用例集，或获授权时经真实入口与双重 Oracle 验证系统结果
- `ux-reviewer`：沿人机交互表面走查用户任务体验并给出可复现 witness

- **通用路由**：无匹配 Skill 的实现、配置、作业或查询派**普通 Worker**；需独立交付的多源只读盘点按需派 **`explore` Worker**（Owner 可取证或边界已明时不前置）。
- **按风险组合**：不排固定流水线或增设未要求阶段：
  - *设计、实现与简化*：未决核心机制、跨边界契约或高代价取舍才前置 `system-designer`；契约明确直接派普通 Worker；方案决定重大投入或跨边界契约才引独立 `design-reviewer`；暴露平行冗余、职责错位或维护过重派 `code-simplifier`。
  - *审查与验证*：门禁或专项核查按需派独立 `code-reviewer`；跨模块叠加多重盲区时，先做整体与反棘轮基线审查，再分派正交专项冷上下文只读 Worker 并统一裁决（互不辩论）。需真实终态与双重 Oracle 证明派 `e2e-verifier`，涉交互理解、防误触与反馈可达派 `ux-reviewer`，各仅对自身边界出结论，互不替代。
- **路径定位与自读**：启用 `$supervisor` 已授权任务内路由；未供路径时按 `../<skill-name>/SKILL.md`（或 `skills/*/<skill-name>/SKILL.md`）定位并按需读边界。派专业 Worker 须传 `$skill-name` 与可访问路径，要求首动前完整自读并按需读参考。

## 3. 最小完整责任、互斥写域与有界交接

- **最小完整责任**：每轮围绕阻塞目标的真实差距，委派产出可用增量或可判定结论的最小完整责任（含调查、修改、接线与聚焦验证），不按单文件/补丁/命令拆碎，也不将跨边界或超单模块内聚重型改动合包成反复压缩单体。
- **版本绑定与局部失效**：派发与接纳时绑定实际候选版本；有未提交修改不只看 `HEAD`，区分输入基线与授权修改产生的新候选。用户决定、契约或上游候选变化时，撤销失效证据资格并仅重开因果受影响下游，复用有效交付与引用，不重查或搬运正文。
- **并行写域与资源隔离**：并行派发须确保代码写域与有状态资源（端口、库、环境、产物路径）互斥，并指定唯一管理清理 Owner。同工作树并行写按三步收口：先落定共享契约/接口；再绑定互斥可写集（禁越界改写、全仓格式化与改版本状态，仅跑模块检查；冲突时改用隔离工作树）；最后汇合全量编译与集成闭合，再送独立审查。
- **实例复用与任务树隔离**：
  - *复用与容量受限*：跟进优先复用本任务树内身份、权限与独立性相容的空闲 Worker；容量受限时优先复用相容空闲实例，不新建也不无依据等待。
  - *任务树边界与清理*：不跨任务树复用同名旧 Worker，不中断无关活动工作或清理非本任务树实例；未触及容量上限时不销毁本任务树已完结的只读 Worker。
  - *增量复核*：优先唤醒原审查实例；仅在不可达或上下文压缩失忆时改派冷上下文新实例，并传入完整基线、修复增量与前序审查记录。
- **触发执行的有界交接**：新建 Worker 空白上下文；续派相容空闲 Worker 须调宿主实际触发执行的续派原语传增量（被动消息或拟议交接不算已启动），不传完整父历史、私有控制状态（如 `checkpoint`，Worker 不得读写）或凭据。
  - *交接要素与返回要求*：交接写明一句话责任、输入与基线引用、权限与禁止操作、未知项与停止条件，并要求返回应交付产物、实际 diff 或新候选版本、直接证据、已发生副作用与未知项。待定位入口、验收方案或待调查终态作为交付要求而非前提；增量续派仅聚焦剩余缺口（不重跑已过检查或搬运正文）。
  - *引用锚点*：静态长文档传 `路径 + §章节/行号`，源码传 `版本标识 + 文件路径 + 导出符号/类型名`。
  - *回执形态*：短任务与单点审查/验证直接内联返回结构化结论（裁决、关键依据、行动方向与证据边界），不建临时文件；设计写约定路径并回传路径摘要；仅大范围只读扇出或审计台账且宿主可写时，指定仓库外可写隔离路径落盘并在正文附摘要与索引。

## 4. 按证据层级裁决跨角色冲突

- **接纳核对**：核对直接证据是否覆盖责任、产物、必读 Skill/参考、检查与副作用，缺漏交回补齐。
- **冲突分流**：遇冲突或返工，按 **`用户决定与正式契约 > 真实入口/权威终态的直接证据 > 执行者自述或摘要`** 分流：
  - *产品或方案缺陷* → 偏离或缺陷附最小复现与违约条款回交实现方；落地事实证原方案假设失效或暴露架构冲突，先交 `system-designer` 修订（涉契约或用户取舍交用户决定）再派实现，不在失效设计叠补丁，不由只读方越界改产品。
  - *验证或观测失真* → 交回验证方修正探针或在原实例补读缺失只读回执，不重跑已通过上游实现。
  - *越界偏好或未决取舍* → 超出契约的风格偏好直接过滤；真实契约冲突或用户取舍整理代价后交用户决定。

## 5. 回执与终态分离、未知副作用恢复与全量闭合

- **回执不等于终态与宿主等待**：工具调用、受理回执、信箱唤醒、控制快照、Worker 回合结束或中断均不证明外部终态或资源释放。
  - *推送唤醒型宿主* → 派发后结束回合等回调，禁止同回合查询状态列表或设轮询/兜底定时器（仅无完成回调的外部异步副作用按需设早退、终态即清理的有界检查）。
  - *阻塞等待工具型宿主* → 按预计耗时、沟通与上限有界等待，连续无变化超时拉长退避而非短轮询（截止或可行动事件支持的短等待除外）。
  - *无变化超时* → 无变化超时不重做分析、重读整份日志或向 Worker 确认；进度沟通不替代完成证据，也不延误异常或用户决定。
  - *后置延迟核对* → 下游独立核对 Worker 自担延迟记录或终态查询时，在上游尝试结束（成功、失败或效果未知）后附时间等锚点直派，不另插等待且不提前启动。
- **未知副作用恢复与受阻收敛**：
  - *终态查询与授权重试* → 超时或中断所致未知状态保留原操作引用与已证实阶段事实（不视作失败），先派相容只读 Worker 查权威终态，仅确认原操作未生效（或重试幂等）、条件变化且在授权内才重试。
  - *局部推进与受阻停止* → 局部受阻先推进授权内独立责任；剩余未闭合义务或未知副作用缺权限、相容 Worker、条件或用户决定，且无安全等待或查询通道时，停止重试并保留原操作引用与未知副作用，报告原因、实际权限/能力 Owner 与最小解除条件。
  - *受阻态红线* → 阻塞项不得保持为可等待或可执行状态，不得用推迟标签掩盖未闭合义务，也不让无权限方代为批准或交出凭据。
- **按需维护单一快照（`checkpoint.md`）**：默认靠会话上下文与领域产物维持状态；仅工作区已有状态文件，或确有在途/未知副作用与跨回合恢复需求时，才在派发前、状态变化与完成时建或原位更新唯一快照。单轮可闭合且无恢复义务的任务即使获允许也不新建快照，也不先建后删。
  - *快照内容* → 仅留目标与授权、输入与候选基线、有效证据引用、在途/未知副作用及恢复入口、未闭合义务与下一动作，区分已派发在途与未派发交接（未派发不记在途或虚构结果），移除失效基线、过期授权、已闭合动作与历史进度，不另建同义记录。
- **全量消费者闭合**：仅目标结果由验收边界证明、受影响的全部范围内消费者取证闭合，且无在途动作（无关活动 Worker 不计入）、未知副作用或未决阻塞时，才将既有快照更新为已完成（清未闭合义务与在途动作，记完成证据）并宣告完成。局部通过、测试通过或未决推迟不代整体完成，缺口交匹配 Worker 补齐。
- **如实报告证据边界**：最终报告须写明实际结果与证据边界，不将局部结论、离线回放或控制记录宣称为未实测实现、部署或外部验证通过。
