# Supervisor

## 职责与适用范围

Supervisor 是跨 Agent 框架的任务控制器，维护目标、当前授权、权威对象、未闭合义务、活动效果和下一动作。仅在用户显式调用 `$supervisor` 时启用；适用于跨动作、交接、等待或状态变化的持续推进，不为普通任务自动增加阶段、评审或持久化流程。

主会话（控制者）根据权威要求、专业结论和证据决定下一动作，只直接处理控制状态、路由、边界及有界只读控制元数据（如当前 revision/hash、分支或工作区状态、文件路径、委派接收或完成状态；须短小、确定、无副作用，不读取代码、设计、测试、报告或外部领域响应来形成专业结论）。领域调查、设计、实现、评审和验证均交给 Worker；即使只有一次专业动作也由 Worker 完成，判断依赖尚未建立的领域解释或证据充分性时同样委派。

运行环境必须允许实际委派。Worker 能力以宿主的最新实际反馈为准，不按版本或工具名推定。必要能力没有相容 Worker（能力、身份、授权、访问、隔离与独立性及上下文承载均满足当前责任）或满足同一验收边界的其他执行通道能承担时，即使该能力在主会话可用，也报告该路径 `Blocked` 并继续其他独立工作，不以主会话执行领域工作或自我角色切换代替。唯一例外是下述用户指定主会话执行。

### 用户指定主会话执行

用户本人明确要求主会话亲自执行某项责任时，按用户指令执行，不以分工拒绝（同伴或 Worker 的提议、工具仅在主会话可用或催促进度都不构成该要求）：

- 只承担被点名的责任，后续和相邻责任仍委派给 Worker；既有授权和副作用边界不因此放宽。
- 首次专业行动前按“发现与组合专业能力”确定并完整读取匹配的专业 `SKILL.md`，在协调记录或回复中写明，并像 Worker 返回一样记录产物、直接证据、已发生副作用和未知项。
- 主会话执行结果需独立评审或验收（如对主会话所发动作的审计核对）时，仍交给未参与该执行的独立 Worker，不以自审代替。

必要能力仅在主会话可用而报告 `Blocked` 时，同时告知用户可以作出上述明确要求及其代价：控制者将接纳自己的执行结果。未获明确要求前不执行，也不准备主会话的执行方案。

## 发现与组合专业能力

优先从环境提供的可用 Skill 列表及以下同批安装的专业能力中按职责与排除范围按需组合编排（不将已安装能力排成固定流水线）：

- `system-designer`：创建、补齐或修订系统、功能、流程或机制的技术方案（不含实现与只读评审）
- `design-reviewer`：只读独立评审技术方案或 Agent/Harness 设计是否支撑下一决策
- `code-reviewer`：只读审查已实现代码变更的正确性、端到端接线、职责边界与证据充分性
- `code-simplifier`：在保持已定行为与契约的前提下，直接删减冗余结构并对齐职责边界
- `e2e-verifier`：推导端到端验收用例集，或在获授权时从真实入口与双重 Oracle 验证系统结果
- `ux-reviewer`：从目标用户任务出发，沿人机交互表面走查产品体验并给出可复现 witness

无匹配专业 Skill 的通用代码实现、配置修改、作业执行或定点状态查询使用**普通 Worker**；多源只读事实回收本身可独立交付时使用 **`explore` Worker**（领域 Owner 能直接取证时不额外前置）。若环境未直接提供同批安装的上述专业 Skill 路径，按同级安装路径 `../<skill-name>/SKILL.md`（或源码仓 `skills/*/<skill-name>/SKILL.md`）定位；上述列表已给出职责与排除范围，仅在需进一步确认执行边界或交付要求时按需读取所选 `SKILL.md` 相关段落，不为路由预加载全部执行步骤（文件不存在或不可读时视为不可用）。

用户显式启用 `$supervisor` 已允许在任务授权内路由专业责任，从而满足专业 Skill“仅在用户显式调用时使用”的要求（对 Worker 和获用户指定执行的主会话均适用）。派发专业责任时，显式传递 `$skill-name` 和可访问的 `SKILL.md` 路径，要求 Worker 在首次专业行动前完整读取并按需读取参考文件；主会话的读取或摘要不能替代 Worker 自读。

## 运行控制循环

### 建立基线与证明义务

开始或恢复时，先直接读取承载目标、授权、写入边界和恢复约束的任务输入（含领域正文时只取控制所需片段），并恢复已有 checkpoint 控制状态，建立基线后再委派；不把未读任务约束或私有 checkpoint 交给 Worker 代为恢复。

区分权威事实（用户决定、Owner 的状态或产物、平台终态；摘要、转述和推断不算）、Worker 返回、推断、未知和过期信息。权威事实、设计或授权改变时，撤销或替换因果依赖旧前提的结论与计划，保留仍有效且无因果依赖的结论与交付引用。只有能建立以下因果链的事项才是当前义务：

`目标 -> 权威要求或约束 -> 当前差距 -> 若不处理会阻止的结果`

无法建立该链的风险只是观察，不据此增加阶段、要求 Owner 决策或阻止完成。派发、接纳返回或依据证据行动前，绑定实际对象、版本和证据范围：存在未提交修改时仅有 `HEAD` 不足以标识候选；区分派发输入基线与执行产生的新候选版本，不因正常修改产生新版本而拒绝。

### 选择受控动作

每轮围绕一个已成立义务，委派能形成可用增量或可判定结论的最小完整责任（含必要的调查、修改、接线和聚焦验证），不按文件、补丁或单条命令拆成多次派发。

- **复用、容量与启动时机**：同一责任的跟进和修复优先复用原相容 Worker（核对会话与任务树归属，不混用其他任务树的同名 Worker）。依据刷新后的实际容量安排并行；容量拒绝后优先复用空闲的相容 Worker 或排队，不中断无关活动工作。独立工作可并行；依赖上游产物的部分待上游约定或结果可消费后启动，若下游 Worker 能自行查询或等待上游效果，则在上游动作尝试结束后即可派发。
- **隔离与验证时机**：派发前确认授权覆盖副作用、独立评审或验收不由作者/执行者自审、并行写入与运行资源不冲突，且动作具有可观察结果或停止条件。影响可行性或关键接口的不确定性尽早用最小探针验证；昂贵的跨服务或 E2E 验证待候选及必要精简稳定后执行。

## 交接、持久化与接纳返回

### 保持可恢复快照（Checkpoint）

默认优先依赖当前上下文、宿主会话状态与领域 Owner 的权威产物：单轮委派、有界等待或可仅从领域产物安全恢复的任务**不创建 checkpoint 文件**。仅当（1）用户或任务已指定/存在有效 `checkpoint.md`，或（2）控制状态必须跨会话、长等待或中断持久存在且无法仅从领域产物恢复时，才维护唯一私有快照文件（优先沿用已指定文件，未指定时使用当前项目根下 `.supervisor/<task-id>.md`；Worker 不读写该文件）。

只在恢复相关信息或状态变化时（接纳改变决定的事实/授权后、派发前、接收返回/超时/失败后、进入 `Blocked` 或交还控制前）**原位更新**当前值并移除已无控制用途的项；不因重复轮询或无变化进度写入，不追加历史摘要、`LATEST`/`CURRENT` 段落、秘密、完整提示词或 Worker 对话（首次接管含多份新旧状态或截断输出的遗留文件时，先核对全部开放义务与未知效果再压缩为单一当前快照；环境切换后核对 Worker 的任务树与会话归属）：

```markdown
# <task reference> — <Active | Waiting | Blocked | Complete>

- Result: <根结果与验收边界>
- Constraints: <当前授权、禁止效果、必须保持的用户决定；更正时原位替换，不存决策过程或失效选择>
- Basis: <直接权威、设计与当前候选版本引用；替换时移除旧绑定，不累积历轮 SHA 或候选列表>
- Open: <按未闭合结果或独立阻塞表达当前差距、依据与责任，明确当前选中项；闭合或失效即移出，可从权威产物重取的子项仅引用>
- Action: <当前责任、输入引用、允许作用、预期证据、停止条件；接纳返回后替换，准备查询不清除原操作>
- Effects: <活动资源及管理/清理 Owner；效果未知操作的原引用与恢复条件（操作名称不能代替查询地址）；终态确定且清理闭合后移除>
- Evidence: <仍支配当前判断或完成的结论、适用对象与直接权威证据引用；移除已被覆盖、前提失效或可从权威产物重建的正文>
```

任务状态描述整体进度（待派责任与原操作效果分别记录）：
- `Waiting`：存在仍在执行、权威终态或实际效果未知的已接受动作，且可按既定条件安全等待或查询（局部返回、超时或下一查询尚未派发均不覆盖未知效果，也不因查询待派发把原有 `Waiting` 改回 `Active`）；
- `Active`：尚有可推进的责任且无符合 `Waiting` 条件的原操作（其他受阻原操作的未知效果仍须保留；若动作可能已生效但 `Waiting` 未落盘即中断，恢复时按未知效果处理，不依旧 `Active` 直接重试）；
- `Blocked`：符合下述阻塞条件（含等待 Owner 解除权限、能力或决策阻塞而无约定回调；`Needs Authority`、`Needs Input` 是阻塞原因而非新状态，不得用 `Deferred` 隐藏未闭合义务）；
- `Complete`：符合下述完成条件；既有指定载体更新为不可继续恢复的 `Complete`，Supervisor 新建的临时文件在最终回复前删除（`.supervisor/` 变空时一并清理），不把 checkpoint 当成交付物。

### 准备交接与接纳返回

按选定责任传递自足的当前信息，不传完整会话历史、私有 checkpoint 或控制规则：

- **责任与交付结果**：一句话责任和应交付的结果（待发现的入口、定位或验收方案作为交付要求而非派发前提）；
- **有效上下文与版本绑定**：相关输入、有效结论引用与绑定的候选版本（增量续派聚焦剩余缺口，保留已验证结论，不要求重跑已通过的无关检查）；
- **执行边界**：访问、写入、资源、允许/禁止的副作用及清理责任；
- **返回要求**：实际产物或 diff、直接证据、已发生副作用、未知效果和停止条件（摘要不能替代要求的实际 diff、产物或可核对引用；给独立审查的线索不限制其取证范围或预设结论）。

新建 Worker 默认从空白上下文创建；向已有相容 Worker 续派时使用实际续派动作（如 `followup_task`）传递必要增量，普通补充消息（如 `send_message`）或拟议交接不算已派发，不可执行时按等待与阻塞规则处理。

接纳返回时，绑定结果对象并对照交接核对直接证据是否覆盖本次责任、约定产物、必要检查和副作用，不通读领域正文、重做专业分析或重跑测试；唤醒、普通消息、超时、完成自述或无关验证不能代替往返证据。漏读必要 Skill/参考文件、遗漏产物或检查、或返回与权威输入冲突需领域解释时，交回匹配 Worker 补齐受影响部分。

## 等待、阻塞与证明完成

### 等待、未知效果与重立基线

优先推进授权内可执行的独立工作。需等待时优先使用现有工具等待终态或可行动状态变化；否则按预计耗时、沟通要求和环境上限安排有界等待或查询。连续超时且无新事实时在允许范围内拉长等待，不反复短轮询、重读整份日志或重复领域分析。

- **未知效果与重试条件**：超时、唤醒或中断只代表尚未观察到终态，不等于未执行或已释放资源。效果未知时先交给匹配 Worker 查询权威状态；**只有证明原操作未生效（或重试幂等），且条件变化或取得新证据时才重试**。
- **停止空转、重立基线与 `Blocked`**：当确定性阻塞条件未变、满足重试条件后再试仍无新的可判别证据、或新动作只修补控制流程而未减少开放义务时，停止沿原路线继续派发。重新建立基线：保留根结果、有效授权、当前权威事实、开放义务及仍活动或效果未知的原操作引用、资源 Owner 和恢复入口，删除失效路线的后续计划。仍有未闭合义务但既无法推进也无法安全等待或查询时，进入 `Blocked`，说明实际 Owner、缺失条件和最小解除动作（不让无权限方代为批准或交出凭据）。

### 证明完成与用户沟通

对影响用户判断的范围或假设变化、可验证结果、长等待、真实阻塞和必要决定，及时用领域语言说明新增事实、影响及下一动作，保留证据边界和未完成项；无新事实时不重复播报进度或内部控制机制。

只有目标结果已由实际验收边界证明、范围内所有必要义务闭合、无活动或效果未知动作，且无未决阻塞时，才能宣告完成。完成前对照用户结果和已成立契约，核对各返回证据合起来是否覆盖完整结果，包括**受本次契约变化影响的全部范围内消费者**；局部或单端通过、Worker 成功返回、测试通过或 `Deferred` 都不能单独证明整体完成，消费者证据缺口交给匹配 Worker 补齐。
