# Checkpoint 文件合同

本合同负责 checkpoint 的载体、内容、状态、写入、恢复和退出。启用条件见主文；文件只保存 Supervisor 私有的当前控制快照，不承担领域产物、过程日志或 Worker 交接职责。

## 选择唯一载体

按以下优先级选择唯一载体：

1. 用户、任务或执行环境已经指定，或当前任务已经建立且仍有效的 checkpoint 文件；
2. 当前任务存在属于交付 Owner、可写的项目根目录时，使用该项目下 `.supervisor/<task-id>.md`；
3. 没有适用的项目载体时，使用操作系统临时目录中的任务专属子目录及 `checkpoint.md`。

多仓任务选择实际拥有交付物或主要副作用的项目根，不因当前目录或可写性选用无关仓库。Task id 优先沿用已有稳定标识；没有时使用任务短名称加随机 UUID 或等价抗冲突后缀，恢复时沿用。

不得另建平行 checkpoint，也不得写入执行框架（harness）或其它工具拥有的全局状态、配置、缓存、日志、可视化、记忆或安装目录，也不得写入仅因可写而选中的其他产品目录。项目内 checkpoint 是运行产物，不得被 stage、commit 或放入 MR；不得为了它修改项目或 Git 配置。若当前执行边界无法保证它不进入产品提交，则该项目载体不适用，使用临时目录。

临时目录只保证当前运行实例和目录生命周期内的恢复，使用时写明限制。存在适用项目载体时遵循上述优先级，不因本次等待较短改用临时目录。

## 文件格式

沿用已有载体的可用格式，只有现有表示妨碍恢复判断时才调整。新建文件默认使用真正的 Markdown；不得把裸 YAML 写入 `.md`。只有环境提供机器消费者、固定 schema 和校验器时才使用 `.yaml`，并按该 schema 校验。

新建 Markdown 可用下面的紧凑结构，删除不适用项；标题、字段名和排列不构成固定 schema：

```markdown
# <task reference> — <Active | Waiting | Blocked | Complete>

- Result: <目标与验收边界>
- Constraints: <当前授权、禁止效果、必须保持的决定>
- Basis: <直接权威与当前候选引用；区分对象所需的版本>
- Open: <全部未闭合结果的最小表示；当前选中的一项>
- Action: <当前责任、输入引用、作用边界、预期证据、停止条件>
- Effects: <活动资源及 Owner；原操作引用、未知效果与安全恢复条件>
- Evidence: <仍决定下一动作或完成的结论及直接证据引用>
```

只有恢复边界、陈旧快照辨别或保留规则实际需要时才增加相应信息。不同项目、候选或效果不可因压缩而失去身份。

## 内容模型与生命周期

Checkpoint 表示当前控制状态。每条信息须影响下一动作、恢复或完成判断；能从当前权威来源安全重取的正文不进入快照，只保留定位与适用范围。同一事实只表达一次，不在目标、义务、动作和证据中反复复制。

| 内容 | 保留的最小控制信息 | 替换或删除条件 |
| --- | --- | --- |
| 结果与约束 | 根结果、验收边界、仍适用的用户决定、授权与禁止效果；没有可靠外部载体的约束必须在这里保留 | 更正时原位替换受影响内容；不保存决策过程或失效选择 |
| 当前依据 | 直接权威、设计与当前候选引用，以及区分可变对象所需的版本 | 对象或权威替换时移除旧绑定；不积累历轮 SHA、文件 hash 或候选目录 |
| 开放义务 | 按未闭合的用户结果或独立阻塞条件表达当前差距、依据与责任；明确当前选中的义务 | 闭合或失效即移出开放集，不转成已完成列表；同一结果下可从权威任务或产物重取的子项仅引用，不复制任务树、测试矩阵或后续步骤 |
| 当前动作与效果 | 当前责任、输入引用、允许作用、预期证据与停止条件；每个仍活动资源的管理/清理 Owner，每个效果未知操作的原引用与恢复条件 | 接纳返回后替换当前动作；终态和效果已确定且清理义务闭合才移除活动记录，不保留已结束的派发、查询或等待历史 |
| 决定性证据 | 当前决定依赖的结论、适用对象与直接权威证据引用 | 不因证据仍然有效就永久保留；能由当前权威证据重建、已被后继结论覆盖或不再支配当前判断的旧条目移除 |

“全部开放义务”要求恢复后不遗漏未完成的用户结果，不要求把每个实现步骤、检查或未来阶段单列。独立授权、阻塞和未知效果必须仍可区分；不能用笼统的“完成剩余工作”隐藏它们。已闭合义务需要的验收证据可由仍适用的报告引用保留，不继续保存过程记录。

已有报告、设计或任务清单是原 Owner 的权威产物，直接引用其位置和适用版本即可；不复制正文，不为 checkpoint 压缩另建历史归档、平行快照或同义证据索引。引用必须在任务恢复边界内可读取；无法可靠重取且仍决定控制的信息保留最小事实，不能用不可访问的会话或临时引用代替它。

## 防止过程累积

每次写入根据上述内容模型更新当前值，并同步删除被替换或已无控制用途的项。返回摘要、旧快照、完成历史和 `LATEST`／`CURRENT` 补充段都不是可追加的数据类型；不等文件膨胀后再定期整理。新信息只有引入了新的必要控制事实才增加内容，新的工具调用、Worker、修订或报告本身不构成增加理由。

正常推进后，快照的信息量应只随当前必要约束、未闭合结果和活动效果变化，不随执行轮数增长。若这些未增加而快照持续增长，写入前检查并去掉重复事实、已闭合项、旧动作与可重取的证据正文；保留当前值及直接引用。真实独立义务或未知效果增加时，不按固定字数或条数删减它们，也不把信息搬到另一份控制日志来绕过这一规则。

版本只用于区分实际对象或陈旧快照，不用文件大小、行数或修改时间证明候选身份。不要求通用 action ID、runtime ref 或执行者身份协议；领域 Owner 提供恢复查询必需的稳定标识时沿用它。

Worker 引用只有仍用于续派、取回结果或查询效果时才保留，并带上恢复所需的任务树或会话归属；不复制宿主注册表、后代树或驻留历史。并行时保留每项仍活动或效果未知的责任，接纳一个返回不能覆盖其它未终结动作。

## 状态语义

状态描述整个任务，待派责任与原操作效果分别记录：

- `Waiting`：存在仍在执行、权威终态或实际效果未知的已接受动作，且可按既定条件安全等待或查询。记录原操作、反馈来源、预期证据和停止条件；同时仍可推进其它独立责任。
- `Active`：尚有可推进的责任，但没有符合 `Waiting` 条件的原操作。其它受阻原操作的未知效果仍须保留，状态变化本身不构成重试依据。
- `Blocked`：仍有未闭合义务，但既无可推进责任，也无法安全等待或查询。记录实际 Owner 和最小解除条件；保留未知效果、原操作引用和恢复入口。等待 Owner 解除权限、能力或决策阻塞，若无约定回调或安全查询条件，属于此状态。
- `Complete`：用户结果已有决定性证据，范围内义务均已闭合，没有活动或效果未知动作，文件不可继续恢复。

局部返回、超时或下一查询尚未派发，都不能覆盖原操作的未知效果。`Needs Authority`、`Needs Input` 是阻塞原因，不是新状态；不得用 `Deferred` 隐藏未闭合义务。

## 写入与恢复

只在恢复相关信息或状态变化时写入：

1. 接纳会改变决定的事实、义务、授权或路线后，在依赖它们的动作前更新；
2. 派发前保存当前依据、责任、边界、预期证据和停止条件，不提前声称已派发；接收、返回、超时或失败后，按整个任务的实际活动与效果更新，再等待、查询或重试。准备查询不会清除原操作，也不会因查询尚未派发把原有 `Waiting` 改成 `Active`；
3. 交还控制或进入 `Blocked` 前更新；完成时按退出规则处理载体。

复用载体已有版本；仅在需要区分陈旧快照时维护 revision。重复等待、轮询、普通进度、能力读取或内部路由没有带来控制事实变化时，不写入。

首次接管遗留文件时，若已有多份新旧状态或截断输出，先分段补齐未读控制内容，核对当前目标、授权、全部开放义务和活动或未知效果，再按上述内容模型替换为单一快照。不能只读可见头尾后覆盖原文件或执行依赖其判断的动作；读取不全时保留原文件并继续回收，无法取得时仅阻塞依赖缺失信息的动作。这是旧文件恢复的兜底，不是维持正常 checkpoint 的方式。

如果动作可能已经产生效果，但对应 `Waiting` 尚未落盘就发生中断，恢复时把效果视为未知，不得依据旧 `Active` 直接重试。恢复后先读取 checkpoint，再刷新可能变化的权威来源。

长任务按上述变化及时保存，不依赖压缩前额外保存。压缩或环境切换后，恢复全部控制事实，再核对必要 Worker 引用的任务树归属、责任和上下文；相同路径不证明是原 Worker。原 Worker 不可用且原动作效果未知时，按主文交给匹配且可访问的 Worker 查询，再决定是否重放；给新执行者自足交接。Agent 会话恢复不等于进程或外部效果恢复。

只有等待、阻塞或以后恢复确实需要用户持有稳定引用时，才报告 checkpoint ref、版本、状态、下一动作或重入条件。交还仍为 `Active` 的恢复任务时，面向用户说明下一动作；完成时只报告领域结果和证据，不把 checkpoint 当成交付物或完成证据。

## 完成后的退出

完成判定成立后，不留下无 Owner、无消费者、无删除条件的运行文件：

- 用户、任务或执行环境指定的既有载体，按其 Owner 的保留规则写成 `Complete`；规则未知时保留载体，不擅自删除，并在载体中标明不可继续恢复；
- Supervisor 新建的临时或项目 checkpoint，如果没有已建立的保留义务，在最终回复前删除；删除前必须已经从权威来源证明完成，并确认没有活动或效果未知动作；
- 已建立保留义务时，写成 `Complete`，记录保留 Owner 和删除触发条件。Checkpoint 不能因“可能以后有用”无限期保留。

## 写入前检查

- 只有一个当前状态，并且状态、当前动作和活动效果一致；
- 每个开放义务符合主文的成立条件，能说明当前差距和受阻结果；
- 用户决定、权威版本或对象状态改变后，依赖旧前提的动作、阻塞、结论和证据已经删除或替换；
- 压缩或替换快照后，仍活动或效果未知操作的可用恢复入口与原引用完整；操作名称不能替代查询所需的地址或定位信息；
- 不同时保留“尚未发生”和“已经完成”的同一事实；
- `Complete` 没有开放义务、活动动作或未知效果；
- 不保存秘密、完整提示词、能力描述或目录、被委派执行者的对话、旧候选、活动历史或未证明的未来阶段；
- 文件位置仍属于当前任务的恢复边界，并且不会进入产品提交。
