# 依赖升级诊断助手

平台组维护 60 个 TypeScript 服务和 12 个共享库，每周收到约 40 份依赖升级提案。现在靠工程师阅读机器人 PR、CI 日志与变更说明逐项判断。请设计一个可复用的依赖升级诊断助手：对一份升级提案形成可追溯的诊断结论和下一步建议；在授权的隔离环境中可以收集额外证据。它应帮助工程师决定是否继续升级、如何缩小修改范围、还需要什么验证。

这次要交付系统与关键诊断策略的设计，不是替样本 PR 直接排障，也不是写固定报错到修复的映射表。给出的包名、版本、日志及合同全部为合成评测材料；没有对应的真实公共包。可以研究适合此类问题的成熟项目或论文，不应在网上寻找这些虚构包的发行说明。

请将设计写入 evals/files/8/design/solution.md，只修改该文件，不执行安装、CI、代码修改、发评论或合并操作。用随附材料说明拟议机制怎样工作；对于尚未执行的检查只能提出预期区分作用，不能虚构结果。
