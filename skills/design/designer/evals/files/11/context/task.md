# 文档到 SOP 的创作能力

希望在对话产品中提供一种能力：业务用户粘贴文档后，系统能够在流程服务中形成忠实表达业务要求、通过正式校验的 SOP 模板；用户之后可以基于已有模板补充和纠正要求。请设计这项能力的整体方案和关键工作机制，供产品与工程团队共同实施。

首期文档直接作为会话文本输入，不做附件读取。流程服务管理模板、配置、正式校验与编译；对话产品应调用其受控工具，不编辑服务文件。允许提议新增或调整工具和正式能力，但要说明必要性及代价。校验成功是可观察的阶段结果，业务含义也必须保持；不要求发布流程或实际执行业务。

business-document.md 是从历史任务实际输入恢复、脱敏后的业务节选，用来检验方案能否处理真实复杂度，不是要求只为这份业务制作专用转换器。current-system.md 是为独立评测制定的模拟当前合同，不声称是原项目现状。团队希望保持现有对话入口和流程服务，无须预先假定单 Agent 或多 Agent。本次设计需要阅读 research-sources.md 中与关键决策相关的原始方法，比较其适用性；可以补充其他成熟实现与论文，不要求采用清单中的方法。可使用本次环境提供的研究工具，无法访问时说明影响。

请将完整设计写入 evals/files/11/design/solution.md；只修改该文件，不实现系统、不直接转换发布业务模板、不联系任何人。
