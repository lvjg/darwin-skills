# 外部客户租户信息调整：业务原文节选

材料性质：来自历史任务实际指定的业务映射文档。以下保留其业务填写值，省略重复的映射判断、表格层级、人员和内部链接。公司、产品、部门以别名替换；这不是完整原文，不评价被省略的人员身份解析。所有“可适配／完全映射”原评价均不作为本评测目标系统的能力证明。没有引入历史任务后续的设计方案。

## 流程信息与范围

外部客户租户基础信息变更时，在决策审批完成后（如需），外部客户客服在运营平台完成实际信息调整。

适用：租户名称、客户联系人信息、商务联系人信息、直销／渠道归属标签、客户所在地与语种调整，以及密码重置。当销售或运营提出租户基础信息变更需求时，进入本流程；本流程场景唯一，不存在场景路由。

不适用：资源交付类型调整（字段规划删除，引导找 N3 执行人沟通）；客户级别调整（由运营按内部规则自行盘点调整，非外部需求驱动）；外部／内部类型标签调整（涉及合同归属、计费主体变更等复杂场景，引导申请方与其销售运营及 N3 执行人沟通）。

## 发起表单与规则

申请表含可重复添加的“调整项”，允许批量修改；未提供最大添加数量。每项包含：

- 站点：必填，保存最终确认的站点对象。用户或 Agent 可用任意站点属性检索；必须从站点权威数据源中确认唯一站点，且运营方精确为“平台运营方 A”。
- 租户：必填，以上一字段确定的站点作为精确条件，并结合 UUID、企业标识或企业名称检索，必须确认唯一租户。
- 字段名称：必填，必须确认唯一租户属性；仅可选择数据来源为“云管平台”且约束条件未标记“不可修改”的属性。
- 目标值：跟随所选租户属性的数据类型。除“密码”外必填，输入值必须满足所选租户属性的约束条件。“密码”作为字段名称时无需提供目标值。

另有不可重复的“补充信息”，包含选填补充批注，随流程传递并向后续节点展示。

申请人为销售时，申请人姓名须与“租户 → 实质客户”链路查询结果对应的“销售姓名”属性值一致。不满足补充校验时阻断发起，告知无权限及联系该租户销售或运营的指引。

## 节点与流转

发起阶段收集申请内容，提交进入 N2。准入失败或取消发生在实例创建前。

N2／销售运营审批：通过后到 N3；退回则回发起阶段。退回必须填写原因和需要修改的内容，批注及批注人展示给发起阶段办理人。

N3／系统调整执行：人工依据调整项清单定位目标租户，完成实际信息调整并记录结果。完成时，若实际办理人与 N4 确认人为同一人，直接结束，否则到 N4。无法执行时必须填写原因，退回发起阶段处理。

N4／需求方确认：由发起人确认。符合预期则结束；不符合预期必须填写说明并返回 N3 重新处理。

## N2 审批组织

按调整项关联销售姓名对应人员的所在部门匹配审批组，各组审批负责的调整项。三个正常审批组分别覆盖不同部门范围：

- 第一组覆盖不在业务拓展部，或在业务拓展部的区域甲、区域乙、区域丙的调整项。
- 第二组覆盖业务拓展部的区域丁或区域戊的调整项。
- 第三组覆盖业务拓展部的区域己或区域庚的调整项。

每组有多名指定候选人，组内或签；不同审批组负责不同调整项，全部组通过且并行办理。无法沿客户链路查到销售姓名、无法匹配销售人员、或人员不在上述部门时，启用节点级兜底审批人，范围为当前节点全部审批组。

申请人与销售运营为同一人时自动审批通过。内容完全重复时跳过已完成审批，复用已有通过结果。审批人只能查看对应数据，没有配置可修改数据范围。

## N3 和 N4 表单与展示

N3 完成时必须提交结果说明；可以写“详见截图”并上传系统截图。涉及密码重置时必须同时提供重置指南。截图选填，另有选填补充批注。N3 无法执行时提交必填的无法执行原因。

N3 正常执行人已指定，另有 Backup 人员，但原文没有定义何种状态触发 Backup。人员本身在本节选中省略。

N4 查看当前流程的全部调整项，以及本次进入 N4 前 N3 完成操作提交的结果说明和截图。

操作关联表单时，本次提交内容默认随实际命中的流转路径展示给直接下游；退回同样适用，未命中的路径和历史轮次不展示。原文未定义额外通知规则或任务时限。
