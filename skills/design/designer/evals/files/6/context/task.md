# 增量构建设计委托

本目录为明确合成的项目和执行回执。现有执行器可运行声明的命令、按前置顺序调度任务，并保留上次输入指纹、输出文件和任务成功状态；文件内容摘要和工具标识均可读取。已有本地共享缓存可按调用方提供的键查询和保存完整成功结果，但不会替调用方判断键是否正确。本次设计计划与复用策略，保留现有执行器和缓存，不要求实现新构建服务。

一次请求必须确保 web-package、server-package、docs 的结果对应本次快照。不能只追求少执行而错误复用，也不要求对未知依赖作没有根据的精确推断。请对 changes.md 的各独立场景给出计划、复用依据和执行顺序，并说明生成任务执行后的信息怎样影响后续决定。场景均从同一个基线开始，不能累积前一场景的变化。

## 执行与缓存事实

所有任务在固定 Linux x86_64 环境执行。明确声明的任务是确定性的，读取输入仅限 tasks.json 声明的源文件、上游产物、参数、工具标识及环境变量；没有网络、时间和其他外部读取。文件元数据不是这些任务的语义输入。缺少输出或上次失败时不构成完整成功结果。缓存不会把部分输出当成功发布。

任务 G 有两个输出，工具版本不同可能产生不同字节，即使版本名相近也没有跨版本等价承诺。下游只读取各自声明的输出文件，不读取生成工具版本。上游重新执行但相应输出字节未变，不会单独改变这些下游的语义输入。

任务 L 的 docs 脚本依赖声明不完整：它除了列出的 manual.md，还会按尚未整理的脚本逻辑读取当前源码快照中的其他普通源文件。已确认它不读任何构建产物、不读网络或系统时钟；全部可能读取的源码都包含在 source_snapshot 中。它只读取声明的 LANG 环境值，工具包含它启动的子工具。工具执行在密闭源码快照中。无法从现有信息得出它的精确文件依赖，但可以完整取得整个快照摘要。不要把列出的 known_inputs 当成完整依赖。任务依赖中除此以外没有未知部分。

所有工具标识代表完整工具包摘要，参数列表有序。基线已经成功生成全部任务的输出，且全部文件和记录完好；基线精确键均命中本地缓存。变化后新输入的缓存结果未知，不能假设命中，也不能声称已实际运行命令。
