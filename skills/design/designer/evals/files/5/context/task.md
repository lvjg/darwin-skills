# 客服反馈归并设计

下面是明确合成的评测输入，不能作为真实产品故障或用户数据引用。客服每周将最多 2,000 条反馈交给现有 Feedback Service。服务已经负责权限、原文持久化、批次导入和保存分组建议；客服工作台负责人工确认。本次设计归并方法，保留服务边界。

客服希望同一可处理问题的报告出现在一起，便于确认影响范围与安排排查。相同词语不代表相同问题，客服也不要求在证据不足时替研发确定根因。分组需要保留原记录关联、关键条件和不确定性；每条原始记录最终都有明确去向。允许暂不归组或关联多个待判断候选，但必须区分这种状态与已确认归属，避免统计时重复算作多个独立报告。

请用 feedback.json 中的输入给出一份分组建议，解释核心判断、形成与修改分组的方式，以及如何检查没有丢失记录或改写原意。面对大批量时可以选择模型、检索或直接规则等办法，但要明确其如何影响判断、成本和错误处理。只交付设计，不实现或调用实际客服服务。没有额外日志能确认这些报告的实际根因。
