# 评测当前系统合同（模拟）

以下事实仅适用于此题，不是原业务项目代码快照。工具名称表示可设计依赖的现有端口，评测环境未运行这些服务，不可声称实际调用成功。

## 对话产品

会话保存原文、用户补充和工具输入输出；可按 message_id 回读完整消息，也可按关键词搜索当前会话。模型每轮有效上下文 24k tokens，某些生产输入可超过 100k tokens；单条回读结果可分片。首期按会话串行执行写工具，不支持分布式多 Agent 协同写入。身份与授权由服务端提供。

## 流程服务

- create_template(request_id) 返回 template_id、revision；相同请求标识重试返回原对象。
- read_template(template_id, selector?) 返回当前修订及选定配置；省略 selector 读取全部。配置通过稳定对象 ID 引用。
- list_methods(kind) 返回方法 ID、用途、版本和摘要；read_method(id, version) 返回参数 Schema、读写的数据、可用时点及正式限制。
- mutate(template_id, expected_revision, request_id, operations) 原子提交一组有类型的 set/remove 操作。成功返回新修订及变更对象；冲突无写入。单对象类型非法拒绝；编辑阶段允许尚未闭合的跨对象引用，正式检查报告这些引用。
- validate(template_id, revision) 返回该版本的结构化诊断，含 code、对象路径、相关引用、消息；结构、引用、方法参数和已登记方法前置条件属于检查范围。不检查模板是否忠实表达输入文档，也不替作者判断业务意图。
- compile(template_id, revision) 只接受正式检查通过的版本，返回编译摘要。服务导出 YAML；发布另需人工操作。

现有可编辑对象：元信息、表单、字段、节点、边及方法调用。字段有 text、number、boolean、enum、attachment、group，group 可设置 repeat 与静态数量约束。节点支持 start、human_task、end；human_task 可配置多个命名操作、不同操作的表单，以及静态指定人员或申请人办理。边可依操作及已登记条件方法分流，允许结构化退回；不接受任意脚本或表达式。

方法目录当前只有：

| 方法 | 正式语义 |
| --- | --- |
| static-persons/v1 | 由已解析人员 ID 形成同一任务的候选人集合，可选任一人或全部人完成 |
| applicant/v1 | 返回本实例申请人 |
| task-actor-equals-applicant/v1 | 比较某次已完成任务实际办理人与申请人 |
| required-fields/v1 | 检查实际提交表单已激活字段的必填项与声明类型 |
| enum-selected/v1 | 判断指定静态枚举字段值是否包含指定选项 |

未列出的领域实体选择、业务校验、分组审批与条件复用并非已实现能力。可以设计扩展，但必须区分业务信息缺失与系统能力缺失，并说明总体成本。现有 read_method 能返回完整合同；不能从方法名字猜测额外行为。

## 修改请求样本（本题合成）

团队需要支持这类后续请求：“以后密码重置也必须由申请人确认，其他调整类型仍按现有规则；保留已有字段和提示文案。”这不是原文补充，用来检验拟议系统对已有模板的修改能力。服务可能同时收到人工编辑；需要能区分用户目标与更新时读到的版本。
