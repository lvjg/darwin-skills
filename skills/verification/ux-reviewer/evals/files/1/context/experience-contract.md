# Workspace-deletion experience contract

- Target user: an organization administrator managing several similarly named workspaces.
- Task: permanently delete the selected secondary workspace without deleting another workspace by mistake.
- Before the final destructive action, the administrator must be able to identify the exact workspace and understand that deletion is permanent.
- A destructive action must not be the accidental default keyboard action when the confirmation first appears.
- Backend authorization, retention and deletion correctness are separate system concerns and are not established by this UX review.

The dialog and its keyboard interaction are owned by the workspace-settings product surface.
