# Darwin

> 让复杂任务从意图出发，以清晰责任和明确对象为边界，以可验证证据闭环。

Darwin 是一组面向 Codex 的系统级工程 Skills，用于在复杂任务中持续对齐目标、事实、责任、交付对象和完成证据。它不增加一套固定流程，而是让系统设计、方案评审、代码与行为验收、E2E、体验走查、实现收敛和长程控制各自拥有清晰边界。

其中七个专业 Skill 可以独立使用；`supervisor` 用于需要跨多项关键操作、交接、等待或权威状态变化保持一致的长程任务。

## 为什么需要 Darwin

复杂任务真正困难的地方，通常不是缺少生成方案或代码的能力，而是工作跨越多个角色、对象和回合后，原始意图、权威事实、决定与授权、专业判断和完成证据逐渐失去一致性。Darwin 通过持续缩小目标与当前结果之间的差距推进长程任务，同时让系统设计、方案评审、代码验收、行为验收、E2E、产品走查和实现收敛保持为彼此独立的专业责任。

| 要解决的痛点 | 整体思路 |
| --- | --- |
| 用户想要的结果在设计和实施过程中逐渐漂移 | 把原始结果、范围、授权和完成标准作为稳定根基；后续方案、动作与判断都必须说明它们如何缩小当前结果差距。 |
| 已经明确授权的动作被反复确认，尚未授权的变化却被自动推进 | 区分可调查事实、需要权限方决定的事项、已有动作授权和平台审批；只有授权不再覆盖当前动作或确实缺少权限方决定时才询问。 |
| 设计、代码实现、行为交付、评审和测试讨论的不是同一个对象 | 为每次设计、交付和验收绑定精确来源与版本；对象变化时只保留仍然有效的结论，并重新判断受影响部分。 |
| 专业作者、修改者和判断者相互替代，责任和结论失真 | 每个专业 Skill 只负责自己的产物或判断；`supervisor` 维护目标、对象、责任方和证据，但不替代事实来源、设计者、评审者、验收者或权限方。 |
| 固定流程关注“进行到哪一步”，却不能回答“现在最该解决什么” | 每轮根据最新事实定位会改变下一决策或完成判断的关键缺口，确认责任方、能力和授权，再选择一个能够产生判别证据的动作。 |
| 测试通过、PR 合并或状态完成被误当成最终结果 | 完成判断回到用户可观察结果：最终对象、有效专业结论和结果证据必须相互绑定，范围内义务、副作用和真实阻塞均已闭合。 |
| 功能 E2E 与产品体验走查混在一起，既无法准确证明系统结果，也容易把审美意见变成阻塞 | E2E 从结果义务和反例推导最小用例集，并用真实入口、可见结果、权威终态和必要副作用证明功能旅程；产品走查独立沿真实用户任务发现内容、层级、布局、交互、反馈和恢复问题。 |
| 连续修补不断引入兼容、恢复和中间状态，系统没有真正收敛 | 当动作不再缩小原始缺口或责任面持续扩大时停止补丁并重新建立基线；结果确认后删除重复和过时路径，收敛为唯一维护路径。 |

## 工作机制

各 Skill 可以独立使用，不存在设计、评审、实施、验收和清理的默认流水线。所有 Skill 都需要用户显式调用，`supervisor` 不会自动加载或调度其他 Skill。长程任务使用 `supervisor` 时，它通过可恢复检查点维护目标、授权、权威对象、未完成事项、证据、正在执行的动作和恢复条件，并根据当前关键缺口寻找事实来源、责任方、专业判断者、结果验证者或权限方。

## Skills

| Skill | 适用场景 | 核心做法 |
| --- | --- | --- |
| [`$supervisor`](skills/supervisor/SKILL.md) | 在跨操作、交接、等待和状态变化的长程任务中维持可恢复控制。 | 维护目标、决定与授权依据、权威对象、未完成事项、证据和活动动作；每轮确认实际责任方并选择一个受授权和风险约束的有效动作，同时处理等待、未知副作用、恢复和重新建立基线。 |
| [`$overview-designer`](skills/overview-designer/SKILL.md) | 创建、补全或重写系统级设计。 | 从可观察结果和真实约束建立问题，比较可行路线与最强简单替代，明确责任、合同、状态、失败和演进语义，再用关键场景挑战并收敛设计。 |
| [`$design-reviewer`](skills/design-reviewer/SKILL.md) | 独立评审尚未实施的技术或行为路线。 | 重建问题和真实起点，检查现有系统边界、能力选择、责任与权威、合同与状态、失败语义、长期结构和迁移可执行性，区分已成立缺陷、决策性未知和用户选择。 |
| [`$code-reviewer`](skills/code-reviewer/SKILL.md) | 验收指定的代码交付，而不是根据 diff 大小、测试数量、已批准设计或实现者声明判断完成。 | 从真实消费者和实际选中路径检查实现、接线、合同、状态、依赖、失败语义、迁移、运维和验证证据；不代替实际行为验收。 |
| [`$behavior-reviewer`](skills/behavior-reviewer/SKILL.md) | 验收由指令、Agent 或模型、工作流、工具路径或呈现渠道共同决定的具体行为。 | 绑定实际加载的运行组合，沿事实、权限、指令优先级、判断、动作、权威结果和最终呈现追踪行为，用对照场景和适配证据区分行为缺陷、代码边界与验证未知。 |
| [`$code-simplifier`](skills/code-simplifier/SKILL.md) | 在目标结果和保留行为已决定或接受后，让现有实现收敛为唯一、可维护的实现。 | 重建受影响的关键执行路径，对每个机制做必要性判断，优先删除和复用，关闭旧入口、旧路径及其再生产机制，并从行为保持、旧路径退出和净简化三个维度证明结果。 |
| [`$e2e-verifier`](skills/e2e-verifier/SKILL.md) | 证明具体产品或系统旅程的功能结果，而不是把低层测试、页面体验或模拟路径当成端到端通过。 | 先固定验收对象和环境，再从关键结果义务与反例形成最小用例集，选择真实入口，以可见结果和权威事实共同判定，并区分产品、验证器、脚手架与环境问题。 |
| [`$ux-reviewer`](skills/ux-reviewer/SKILL.md) | 从目标用户完成真实任务的过程发现产品体验问题，而不是证明后台或系统功能正确。 | 沿代表性人机路径检查内容、信息层级、导航、动作、反馈、布局、可达性和恢复，用可复现证据将发现区分为阻断缺陷、实质缺陷、风险、偏好和非体验功能偏差。 |

## 安装

使用 [Agent Skills CLI](https://github.com/vercel-labs/skills)，需要 Node.js 18 或更高版本。

查看仓库中的 Skills：

```sh
npx skills add lvjg/darwin-skills --list
```

将全部 Skills 全局安装给 Codex：

```sh
npx skills add lvjg/darwin-skills --skill '*' --global --agent codex --yes
```

只安装一个 Skill：

```sh
npx skills add lvjg/darwin-skills --skill design-reviewer --global --agent codex --yes
```

如需项目级安装，去掉 `--global`。

## 更新

重新运行全量安装命令，更新或补齐 Darwin 仓库中的全部 Skill：

```sh
npx skills add lvjg/darwin-skills --skill '*' --global --agent codex --yes
```

从 v0.1.0 升级时，还需要按 [MIGRATIONS.md](MIGRATIONS.md) 核对映射并删除旧名称。

## 维护

修改 Skill、README 或迁移说明后，运行仓库打包检查：

```sh
ruby scripts/check-packaging.rb --base HEAD
```

Pull Request 和 `main` 分支上的相同检查由 [Packaging workflow](.github/workflows/packaging.yml) 执行。

## 全局工程原则

[`codex/AGENTS.md`](codex/AGENTS.md) 是独立的 Codex 全局工程原则模板，不是 Skill，也不会由 Agent Skills CLI 安装。使用前应先审阅其内容，再决定是否作为全局 `AGENTS.md`。
